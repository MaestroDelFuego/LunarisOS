Introduction

NEO98 LunarisOS is a hobby operating system written mainly in C and some assembly language. It features:

  • Support for VGA text mode graphics
  • Simple GUI windowing system
  • Mouse input via PS/2 protocol
  • Modular kernel design with drivers and libraries

🌙 LunarisOS - neo98 Folder Structure

This document provides a detailed view of the neo98 directory inside LunarisOS, including source files, roles, and technical purpose of each part in the OS development pipeline.

📁 Root (neo98/)

  • Makefile – Controls compilation of the kernel, GUI, and drivers.
  • linker.ld – Linker script for kernel memory layout (sets kernel entry point, stack, and segments).
  • start.s – Initial assembly code that runs before C code (sets up stack, jumps to kernel_main).
  • multiboot.s – Ensures the OS is compliant with the Multiboot specification (used by GRUB).
  • start.o, multiboot.o – Compiled object files from the above assembly sources.
  • neo98.iso – Bootable ISO image generated during build.

📁 boot/

  • grub.cfg – Bootloader config for GRUB to load the kernel.

📁 build/iso/boot/

  • kernel.bin – Final kernel binary ready to boot.

📁 gui/

  • gui.c – Core GUI logic (likely drawing windows, elements).
  • gui.o – Compiled version.

📁 gui/taskbar/

  • taskbar.c – Code for displaying and managing the taskbar.

📁 include/

  • gui.h – GUI-related definitions (functions for drawing, screen buffer).
  • idt.h – Interrupt Descriptor Table definitions.
  • io.h – I/O port interaction macros (inb, outb).
  • mouse.h – Mouse driver interfaces.
  • stdio.h, string.h – Custom versions of C stdlib.
  • taskbar.h – Header for taskbar logic.
  • types.h – Typedefs for uint32_t, bool, etc.
  • vga.h – Interface for VGA text and pixel mode graphics.

📁 kernel/

  • main.c – Entry point of the kernel (kernel_main function).
  • idt.c – Sets up interrupt handlers.
  • *.o – Compiled object files.

📁 kernel/asm/

  • idt_asm.asm – Assembly stubs for ISRs (interrupt service routines).
  • mouse_irq.asm – Low-level mouse interrupt handlers.

📁 kernel/drivers/

  • vga.c – Direct control of video memory for rendering text/pixels.
  • io.c – Functions for interacting with hardware I/O.
  • mouse.c – PS/2 mouse initialization and handling.

📁 lib/

  • stdio.c – Implements basic printing/logging (like `printf`).
  • string.c – Custom string functions (`strlen`, `strcmp`, etc.).

📁 Empty/Placeholder Folders

  • apps/
  • fs/
  • gui/windows/

Note: These folders are likely planned for future expansion (apps, filesystem, window manager, etc.)

Boot Process

  • Multiboot Header (multiboot.s)
    The Multiboot header enables the OS to be loaded by GRUB or compatible bootloaders. It contains a magic number, flags, and a checksum. 
    section .multiboot
  dd 0x1BADB002           ; magic number identifying multiboot
  dd 0x00010003           ; flags specifying features used (e.g., memory info)
  dd -(0x1BADB002 + 0x00010003)  ; checksum to validate header

    Explanation: This assembly code declares the Multiboot header that must be placed early in the binary. The checksum ensures the sum of all three dwords is zero for validation.

  • Entry Point (start.s)
    The initial entry point disables interrupts and jumps into the kernel's main function. 
    global _start

_start:
  cli                 ; disable interrupts
  call kernel_main    ; call the main C kernel function

.halt:
  hlt                 ; halt CPU until next interrupt
  jmp .halt           ; infinite loop to keep CPU halted

    Explanation: Upon boot, interrupts are disabled to avoid race conditions. The kernel_main function (in C) initializes the system. The infinite loop with hlt keeps the CPU in a low-power state.

Kernel

Main Loop (kernel/main.c)

This is the core loop that initializes all drivers and GUI, then continuously updates the screen and mouse cursor.

void kernel_main() {
  vga_clear();
  gui_init();
  mouse_init();

  draw_cursor(mouse_x, mouse_y);

  while (1) {
      gui_present();
      draw_cursor(mouse_x, mouse_y);
  }
}

Explanation: First, the VGA screen is cleared. GUI and mouse systems are initialized. Then it draws the cursor at the current mouse coordinates. The infinite loop continually refreshes the GUI and cursor, ensuring the display is updated with any changes.

VGA Driver (kernel/drivers/vga.c)

The VGA driver manages text mode output using an offscreen buffer for double-buffering.

void vga_flush() {
  memcpy((void*)VGA_MEMORY, vga_buffer, VGA_WIDTH * VGA_HEIGHT * 2);
}

void vga_clear() {
  for (int i = 0; i < VGA_WIDTH * VGA_HEIGHT; i++) {
      vga_buffer[i] = ' ' | (COLOR_BLACK << 8);
  }
}

Explanation: The vga_flush function copies the offscreen buffer to the VGA memory region, updating the displayed text. The vga_clear fills the buffer with blank spaces with black background color, effectively clearing the screen.

Mouse Driver (kernel/drivers/mouse.c)

Handles PS/2 mouse input through IRQ interrupts, packet parsing, cursor position updates, and drawing.

void mouse_isr() {
  static uint8_t mouse_packet[3];
  static int mouse_packet_index = 0;

  mouse_packet[mouse_packet_index++] = inb(0x60);
  if (mouse_packet_index == 3) {
      mouse_packet_index = 0;
      // Parse packet, update mouse_x, mouse_y coordinates
      // Redraw cursor at new position
      send_eoi();
  }
}

Explanation: Each mouse interrupt delivers one byte of a 3-byte packet. Once all three bytes arrive, the code decodes movement and button states. The cursor coordinates are updated and redrawn. An End-Of-Interrupt (EOI) signal is sent to the Programmable Interrupt Controller to acknowledge processing.

GUI System (gui/gui.c)

Draws simple windows with a colored title bar and centered text.

void gui_draw_window(int x, int y, int width, int height, const char* title) {
  vga_draw_rect(x, y, width, height, COLOR_LIGHTGRAY);
  vga_draw_rect(x, y, width, 1, COLOR_BLUE); // title bar
  vga_print_centered(x, y, width, title, COLOR_WHITE);
}

Explanation: This function draws a rectangular window filled with a light gray background. The top row is colored blue as a title bar, with the window title centered in white text. It relies on VGA drawing primitives.

Build and Link

The build system uses make with GCC targeting i386 architecture.

gcc -m32 -ffreestanding -c kernel/main.c -o kernel/main.o
ld -m elf_i386 -T linker.ld -o lunaris.bin multiboot.o start.o kernel/main.o ...

Explanation: The kernel is compiled as a freestanding 32-bit binary with no standard library dependencies. The linker script (linker.ld) defines memory layout and entry points.

Practical Automation

While the Build and Link section showed the manual process, in practice LunarisOS uses a Makefile to fully automate compilation, linking, ISO creation, and running in QEMU. This ensures consistency and saves time when rebuilding the kernel. 

ISO_NAME = neo98.iso
BUILD_DIR = build/iso
KERNEL = $(BUILD_DIR)/boot/kernel.bin

C_SOURCES = kernel/main.c kernel/drivers/vga.c gui/gui.c lib/string.c lib/stdio.c kernel/drivers/mouse.c
ASM_SOURCES = start.s multiboot.s
OBJECTS = kernel/main.o kernel/drivers/vga.o gui/gui.o lib/string.o lib/stdio.o kernel/drivers/mouse.o start.o multiboot.o

ASM_BOOT_OBJS = multiboot.o start.o
OTHER_OBJS = kernel/main.o kernel/drivers/vga.o gui/gui.o lib/string.o lib/stdio.o kernel/drivers/mouse.o

all: clean iso

%.o: %.c
	i686-elf-gcc -ffreestanding -m32 -nostdlib -Iinclude -c $< -o $@

%.o: %.s
	i686-elf-as $< -o $@

kernel: $(OBJECTS)
	mkdir -p $(BUILD_DIR)/boot
	i686-elf-ld -T linker.ld -o $(KERNEL) $(ASM_BOOT_OBJS) $(OTHER_OBJS)

iso: kernel
	mkdir -p $(BUILD_DIR)/boot/grub
	cp boot/grub.cfg $(BUILD_DIR)/boot/grub/
	grub-mkrescue -o $(ISO_NAME) $(BUILD_DIR)

run: iso
	qemu-system-i386 -cdrom $(ISO_NAME)

clean:
	rm -rf build *.iso *.o

Target Breakdown

  • all – Cleans previous build artifacts, then builds the bootable ISO.
  • %.o: %.c – Rule for compiling any C file into an object file using i686-elf-gcc.
    • -ffreestanding → No assumptions about a host environment or libraries.
    • -m32 → Target 32-bit x86.
    • -nostdlib → Don’t link to the host’s libc.
    • -Iinclude → Use project’s own header files.
  • %.o: %.s – Assembles .s files into object files with i686-elf-as.
  • kernel – Links all compiled objects into the kernel binary (kernel.bin) using the linker script.
    • ASM_BOOT_OBJS → Startup assembly (multiboot + entry code).
    • OTHER_OBJS → Kernel C drivers, libraries, and main loop.
  • iso – Packages the kernel into a bootable GRUB ISO:
    • Creates build/iso/boot/grub.
    • Copies grub.cfg into the ISO.
    • Runs grub-mkrescue to produce neo98.iso.
  • run – Boots the ISO directly in QEMU (32-bit mode).
  • clean – Removes build artifacts (build/, .iso, .o).

Search Function

This search input filters the navigation links on the sidebar:

document.getElementById('search-input').addEventListener('input', function() {
  const filter = this.value.toLowerCase();
  const links = document.querySelectorAll('#nav-list a');
  links.forEach(link => {
    const text = link.textContent.toLowerCase();
    link.style.display = text.includes(filter) ? 'block' : 'none';
  });
});
